# Свой CORS-прокси для плагина «Кинопоиск»

Плагину нужно обращаться к API Кинопоиска (`graphql.kinopoisk.ru`), а он не отдаёт
CORS-заголовки — браузер Лампы такой запрос блокирует. Оригинальный плагин решает это
чужим Google Apps Script, которому вы отдаёте свой OAuth-токен.

Здесь вместо него — **ваш собственный Cloudflare Worker**. Токен уходит только туда.

В Worker уже прошиты оба нужных запроса, поэтому **ничего вручную вставлять не надо**:
он сам узнаёт ваш `kpId` по токену и запрашивает список «Буду смотреть».

## 1. Развернуть Worker

Через панель (ничего устанавливать не нужно):

1. <https://dash.cloudflare.com> → **Workers & Pages** → **Create** → **Create Worker**.
2. Имя, например `kp-proxy` → **Deploy**.
3. **Edit code** → удалите шаблон → вставьте целиком `worker.js` → **Deploy**.

Адрес получится вида `https://kp-proxy.<ваш-поддомен>.workers.dev`.

Через CLI (если установлен `wrangler`):

```bash
wrangler login
cd proxy/cloudflare-worker
wrangler deploy
```

## 2. Переменная `PROXY_KEY` (рекомендуется)

Worker → **Settings** → **Variables and Secrets** → **Add**:

- Имя: `PROXY_KEY`, тип: **Secret**, значение: длинная случайная строка.

Затем **Deploy**. Без этой переменной прокси открыт всем, кто знает адрес.

Проверка:

```bash
curl https://kp-proxy.<ваш-поддомен>.workers.dev/health
# {"ok":true,"has_key":true}
```

## 3. Подключить в Лампе

Настройки → **Кинопоиск** → блок **Свой прокси**:

- **Адрес прокси** — `https://kp-proxy.<ваш-поддомен>.workers.dev/kp`
- **Ключ прокси** — то же значение, что в `PROXY_KEY`

Затем перезапустите Лампу и зайдите в раздел «Кинопоиск».

Если плагин раздаётся с того же домена, что и Worker, адрес прокси можно не
указывать — он определится сам.

## Как это работает

Один запрос плагина превращается в два запроса к Кинопоиску:

1. `UserCanCreateKid` — по OAuth-токену узнаём `kpId` пользователя;
2. `UserReactionMoviesPage` — список реакций типа `PLANNED_TO_WATCH`; Кинопоиск
   отдаёт максимум 20 за запрос, поэтому Worker добирает страницы пачками по 6
   параллельно (до 1000 позиций). Поле `total` в ответе не приходит — конец
   списка определяется по неполным страницам, поэтому запрос может идти долго:
   плагин ждёт ответ до 3 минут.

Оба документа взяты из открытого кода и проходят белый список Кинопоиска
(любой самодельный запрос шлюз отклоняет с `the query is not allowed`).
Ответ переупаковывается в структуру `data.userProfile.userData.plannedToWatch`,
которую ждёт плагин, — поэтому сам плагин менять не нужно.

Токен передаётся в заголовке `Authorization: OAuth …` к Кинопоиску и в теле POST
от плагина; в URL он не попадает и нигде не логируется.

## Если Кинопоиск что-то поменяет

Симптом: плагин показывает ошибку Кинопоиска или пустой список, в консоли Лампы —
ответ с `errors`. Тогда нужно обновить документы `ID_QUERY` / `WATCHLIST_QUERY`
в начале `worker.js`: взять актуальные из открытого кода или из DevTools на
kinopoisk.ru (Network → фильтр `graphql` → Payload → поле `query`).

## Ограничения

- Бесплатный тариф Workers: 100 000 запросов в сутки.
- Ответы не кэшируются: список обновляется при каждом открытии раздела.
- Загружаются первые 50 позиций — как и в оригинальном плагине.
